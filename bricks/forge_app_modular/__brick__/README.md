# {{name}}

A Flutter application generated by [Flutter ForgeKit CLI][forgekit] using the
**Flutter Modular** architecture profile.

## Getting started

```sh
flutter pub get
dart run build_runner build
flutter run
```

Serialization code is generated rather than committed, so `build_runner` has to
run once after checkout and again after any change to a DTO or model. Use
`dart run build_runner watch` while working.

Dependency injection is handled by Flutter Modular's own binds rather than
`injectable`, so DI does not require codegen on this profile.

## Project layout

```
lib/
  app/
    app.dart        Application widget
    app_module.dart Root module: mounts feature modules and shared services
    home_page.dart
  core/
    state/          Shared state helpers
    theme/          Theme and theme controller
  modules/
    <feature>/
      <feature>_module.dart  Routes and binds for this feature
      data/                  Repository and API service
      presentation/          Controller, state, and page
  main.dart
```

Each module owns its own routes and binds. Routing is Modular's, so `--router`
is not applicable on this profile. `forgekit doctor` checks that every generated
module is mounted in `app_module.dart`.

## Common tasks

| Task | Command |
|---|---|
| Add a feature module | `forgekit add feature orders` |
| Add a screen | `forgekit add screen orders order_detail` |
| Add a service | `forgekit add service session` |
| Run tests with coverage | `forgekit test` |
| Check the architecture | `forgekit doctor` |
| Preview a change | `forgekit --dry-run add feature orders` |
| Undo the last generation | `forgekit rollback` |

Run `forgekit --help` for the full command surface.

**Not available on the Modular profile in this release:** `forgekit add model`,
`add function`, `add usecase`, `add test model`, `add test function`,
`import openapi`, `rename feature`, `remove feature`, and `doctor --fix`. These
are Clean-profile only and will refuse to run rather than write to the wrong
place. Write those files by hand for now.

## A note on generated markers

`lib/app/app_module.dart` contains comments like `// forgekit:modules` and
`// forgekit:services`, and each feature module contains `// forgekit:routes`.
ForgeKit inserts generated registrations at these markers, so removing one will
break the next `forgekit add feature` or `forgekit add screen`. Leave them in
place.

## Configuration

`forgekit.yaml` records this project's architecture, state management, router,
and generation settings. Change it with `forgekit config set <key> <value>`
rather than by hand — a manual edit that disagrees with the actual folder layout
will make generation write to the wrong place.

Note that `forgekit config set` rewrites the file from ForgeKit's own template,
so comments and unrecognised keys in `forgekit.yaml` are not preserved.
