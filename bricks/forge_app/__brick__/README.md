# {{name}}

A Flutter application generated by [Flutter ForgeKit CLI][forgekit] using the
**Clean** architecture profile.

## Getting started

```sh
flutter pub get
dart run build_runner build
flutter run
```

Serialization and dependency-injection code is generated rather than committed,
so `build_runner` has to run once after checkout and again after any change to a
DTO, model, or `@injectable` class. Use `dart run build_runner watch` while
working.

## Project layout

```
lib/
  core/
    di/            Dependency-injection modules (get_it + injectable)
    domain/        Shared use-case and API-result contracts
    presentation/  App shell, theme, shared widgets, state helpers
  features/
    <feature>/
      data/        API services and repository implementations
      domain/      Repository contracts and use cases
      presentation/ Screens, state, and route registration
  main.dart
```

Feature code depends inward on `domain`; `presentation` never imports `data`
directly. `forgekit doctor` checks this contract.

## Common tasks

| Task | Command |
|---|---|
| Add a feature | `forgekit add feature orders` |
| Add a screen | `forgekit add screen orders order_detail` |
| Add a model from JSON | `forgekit add model Order` |
| Add an API operation | `forgekit add function orders fetch_orders` |
| Run tests with coverage | `forgekit test` |
| Check the architecture | `forgekit doctor` |
| Preview a change | `forgekit --dry-run add feature orders` |
| Undo the last generation | `forgekit rollback` |

Run `forgekit --help` for the full command surface.

## A note on generated markers

Files such as `lib/core/presentation/app/app.dart` contain comments like
`// forgekit:named-routes`. ForgeKit inserts generated registrations at these
markers, so removing one will break the next `forgekit add feature` or
`forgekit add screen`. Leave them in place.

## Configuration

`forgekit.yaml` records this project's architecture, state management, router,
and generation settings. Change it with `forgekit config set <key> <value>`
rather than by hand — a manual edit that disagrees with the actual folder layout
will make generation write to the wrong place.

Note that `forgekit config set` rewrites the file from ForgeKit's own template,
so comments and unrecognised keys in `forgekit.yaml` are not preserved.
